## 1. 개요

### 1.1 목적

원본 문서(PDF, Word, 텍스트 등)를 LLM이 읽고 **마크다운 위키를 직접 작성·갱신·점검**하는 시스템을 만든다.
사용자는 위키에 질문하거나 위키를 직접 읽는다.

이 방식은 Andrej Karpathy가 제안한 "LLM Wiki" 패턴을 따른다.
질문할 때마다 원문 조각을 검색하는 RAG와 달리, 지식을 위키 페이지로 **미리 정리해 축적**한다.

### 1.2 범위

- 포함: 문서 수집(ingest), 질의(query), 답변 저장, 위키 점검(lint), 위키 열람, 작업 로그, 작성 규칙 편집, 요청별 모델·추론 강도 선택
- 제외: 사용자 인증·권한, 다중 사용자 동시 편집, 벡터 검색, OCR, 위키 페이지 수동 편집 UI, 배포·운영 자동화

### 1.3 용어

| 용어 | 정의 |
|---|---|
| 원본 (raw source) | 사용자가 추가한 문서. 시스템이 수정하지 않는다 |
| 위키 페이지 (page) | LLM이 작성한 마크다운 파일. 메타데이터(frontmatter)와 본문으로 구성 |
| slug | 페이지 식별자이자 파일명. 예: `access-control`, `가디언-ac-100` |
| 위키 링크 | 본문 안의 `[[slug]]` 표기. 다른 페이지를 가리킨다 |
| 목차 (index.md) | 모든 페이지의 slug·제목·한 줄 요약 목록. 시스템이 자동 생성 |
| 로그 (log.md) | 모든 작업의 시간순 기록. 덧붙이기만 한다 |
| 스키마 (AGENTS.md) | LLM이 위키를 쓸 때 따르는 작성 규칙. 사람이 편집한다 |
| effort | OpenAI 추론 모델의 reasoning effort (추론 강도) |

### 1.4 사용자

| 사용자 | 목적 |
|---|---|
| 지식 관리자 | 문서를 추가하고, 작성 규칙을 조정하고, 점검 결과를 확인한다 |
| 일반 사용자 | 위키에 질문하고 위키 페이지를 읽는다 |

## 2. 전체 설명

### 2.1 시스템 구성

```
[브라우저] ── Streamlit 프론트엔드 (:8501) ── HTTP/JSON ── FastAPI 백엔드 (:8000) ── OpenAI Responses API
                                                               │
                                                        파일 저장소 data/
```

- 백엔드와 프론트엔드는 **별도 프로세스**로 실행한다.
- 데이터는 **DB 없이 파일**로 저장한다. 위키 자체(마크다운 파일)가 저장소다.

### 2.2 제약 사항

| ID | 제약 |
|---|---|
| C-01 | 언어: Python 3.12 |
| C-02 | 백엔드: FastAPI, 프론트엔드: Streamlit |
| C-03 | LLM: OpenAI Responses API. API 키는 환경변수 `GPT_API`에서 읽는다 |
| C-04 | 기본 모델: `gpt-6-luna`, 기본 effort: `medium` |
| C-05 | DB를 쓰지 않는다. 모든 데이터는 `data/` 폴더의 파일이다 |
| C-06 | OS: Windows 11 (PowerShell)에서 동작해야 한다. 파일 입출력은 모두 UTF-8 |
| C-07 | 단일 프로세스·단일 사용자를 전제로 한다 |

### 2.3 가정

- 위키 규모는 수백 페이지 이하다. 이 규모에서는 목차만 보고 LLM이 관련 페이지를 고를 수 있다.
- 업로드 문서의 내용이 OpenAI로 전송되는 것을 사용자가 허용한다.

## 3. 기능 요구사항

우선순위: **M** = 필수, **S** = 권장

### 3.1 문서 수집 (Ingest)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-ING-01 | 파일을 업로드하면 텍스트를 추출해 위키에 반영한다. 지원 형식: `.pdf .docx .txt .md .markdown .csv .json .html .htm .xml .log` | M |
| FR-ING-02 | 제목과 본문 텍스트를 직접 입력해 반영할 수 있다 | M |
| FR-ING-03 | 원본은 `data/raw/`에 원래 파일명으로 저장한다. 같은 이름이 있으면 `이름-2.확장자`, `이름-3.확장자` 순으로 바꾼다. 파일명에 쓸 수 없는 문자는 `_`로 바꾼다 | M |
| FR-ING-04 | 원본마다 `source` 유형 페이지를 하나 만든다 (slug는 `source-`로 시작) | M |
| FR-ING-05 | 원본에 나오는 중요한 개체·개념·주제 페이지를 새로 만들거나 **기존 페이지를 갱신**한다 | M |
| FR-ING-06 | 기존 페이지를 갱신할 때는 기존 내용을 보존하며 새 정보를 통합한다. 기존 내용과 충돌하는 정보는 덮어쓰지 않고 `## 상충되는 정보` 섹션에 출처와 함께 기록한다 | M |
| FR-ING-07 | LLM이 본문을 보지 못한 기존 페이지와 같은 slug를 반환하면, 덮어쓰지 않고 기존 본문 뒤에 `## 추가 내용 (원본파일명)` 섹션으로 덧붙인다 | M |
| FR-ING-08 | 페이지의 `sources` 메타데이터에 반영한 원본 파일명을 누적한다 | M |
| FR-ING-09 | 반영이 끝나면 목차를 다시 만들고 로그를 남긴다 | M |
| FR-ING-10 | 원본이 `MAX_SOURCE_CHARS`(기본 150,000자)보다 길면 앞부분만 반영하고, 응답과 로그에 그 사실을 표시한다 | M |
| FR-ING-11 | 응답에는 원본 저장 파일명, 원본 제목, 생성·수정된 slug 목록, 잘림 여부, LLM 작업 요약, 사용한 모델·effort를 담는다 | M |
| FR-ING-12 | 텍스트를 추출하지 못하면(빈 문서, 스캔 PDF) 400 오류를 반환한다. 지원하지 않는 형식도 400 | M |
| FR-ING-13 | 업로드 크기는 `MAX_UPLOAD_MB`(기본 20MB)로 제한하고, 넘으면 413 오류를 반환한다 | S |
| FR-ING-14 | 텍스트 파일은 UTF-8(BOM 포함)로 읽고, 실패하면 CP949로 읽는다 | M |

### 3.2 질의 (Query)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-QRY-01 | 질문을 받으면 LLM이 목차를 보고 관련 페이지를 최대 `MAX_QUERY_PAGES`(기본 8)개 고른다 | M |
| FR-QRY-02 | 고른 페이지만 근거로 답한다. 각 주장 뒤에 근거 페이지를 `[[slug]]`로 표시한다 | M |
| FR-QRY-03 | 근거가 부족하면 그렇다고 밝히고, 추가하면 좋을 자료를 제안한다 | M |
| FR-QRY-04 | 위키가 비어 있으면 LLM을 호출하지 않고 안내 문구를 반환한다 | M |
| FR-QRY-05 | 응답에는 답변, 참고한 slug 목록, 사용한 모델·effort를 담는다 | M |
| FR-QRY-06 | 질의도 로그에 남긴다 (질문, 참고 페이지, 모델) | M |
| FR-QRY-07 | 답변을 `analysis` 유형 페이지로 위키에 저장할 수 있다. slug는 `analysis-<제목>`이고, 중복되면 `-2`, `-3`을 붙인다. 저장 시 LLM을 호출하지 않는다 | M |

### 3.3 점검 (Lint)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-LNT-01 | LLM이 위키 페이지들을 읽고 문제를 찾는다. 유형: `contradiction`(모순), `stale`(오래된 정보), `missing_page`(빠진 페이지), `missing_link`(빠진 링크), `duplicate`(중복), `other`(기타) | M |
| FR-LNT-02 | 각 문제에는 관련 slug 목록, 설명, 개선 제안을 담는다 | M |
| FR-LNT-03 | 코드로 **깨진 링크**(존재하지 않는 slug로의 링크)와 **고아 페이지**(다른 페이지에서 링크되지 않는 페이지)를 찾는다 | M |
| FR-LNT-04 | LLM에 넘기는 분량은 `MAX_LINT_CHARS`(기본 200,000자)로 제한한다. 일부만 점검했으면 점검한 페이지 수와 전체 페이지 수를 함께 반환한다 | M |
| FR-LNT-05 | 점검 결과 건수를 로그에 남긴다 | M |
| FR-LNT-06 | 점검은 문제를 보고만 하고 위키를 자동으로 고치지 않는다 | M |

### 3.4 위키 열람

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-WIK-01 | 전체 페이지의 메타데이터 목록을 조회할 수 있다 | M |
| FR-WIK-02 | 페이지 하나를 조회하면 메타데이터, 본문, 나가는 링크, **역링크**(이 페이지를 링크하는 페이지)를 반환한다 | M |
| FR-WIK-03 | 목차(index.md), 로그(log.md), 원본 파일 목록(이름, 크기, 추가 시각)을 조회할 수 있다 | M |
| FR-WIK-04 | slug 형식에 맞지 않거나 존재하지 않는 페이지 요청은 404를 반환한다 (경로 조작 방지) | M |

### 3.5 작성 규칙 (Schema)

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-SCH-01 | 첫 실행 시 기본 작성 규칙 파일 `data/AGENTS.md`를 만든다 | M |
| FR-SCH-02 | 작성 규칙을 조회·수정할 수 있다. 수정 내용은 다음 ingest부터 LLM 지시문에 반영된다 | M |
| FR-SCH-03 | 규칙 수정도 로그에 남긴다 | S |

### 3.6 모델 선택

| ID | 요구사항 | 우선순위 |
|---|---|---|
| FR-MDL-01 | 선택 가능한 모델과 모델별 지원 effort 목록을 조회할 수 있다 | M |

| FR-MDL-03 | 목록에 없는 모델이나, 해당 모델이 지원하지 않는 effort는 400 오류로 거부한다 | M |
| FR-MDL-04 | 지원 모델 (2026-10 기준, 실제 API 호출로 확인): | M |

### 3.7 프론트엔드 (Streamlit)

| FR-UI-05 | 문서 추가 탭: 여러 파일 업로드, 파일별 진행 상태와 결과(제목, 작업 요약, 생성·수정 수, 잘림 경고). 텍스트 직접 입력 폼. 추가된 원본 목록 표 | M |
| FR-UI-06 | 위키 탭: 왼쪽에 검색(제목·요약), 유형 필터, 페이지 목록. 오른쪽에 제목, 메타정보, 본문, 연결된 페이지·역링크 버튼(누르면 이동, 없는 페이지는 비활성). 목차 원문 보기 | M |
| FR-UI-07 | 본문의 `[[slug]]`는 `` `📄 slug` `` 형태로 바꿔 보여준다 | M |
| FR-UI-08 | 점검 탭: 실행 버튼, 지적 건수·깨진 링크·고아 페이지 지표, 문제별 카드(유형, 설명, 제안, 관련 페이지), 깨진 링크 표, 고아 페이지 목록, 부분 점검 경고 | M |
| FR-UI-09 | 로그 탭: log.md를 마크다운으로 보여준다 | M |
| FR-UI-10 | 규칙 탭: AGENTS.md를 편집하고 저장한다 | M |
| FR-UI-11 | 백엔드에 연결하지 못하면 오류와 실행 안내를 보여주고 렌더링을 멈춘다. API 오류는 상태 코드와 `detail`을 보여준다 | M |
| FR-UI-12 | 백엔드 주소는 환경변수 `BACKEND_URL`(기본 `http://localhost:8000`)에서 읽는다 | M |

## 4. 비기능 요구사항

| ID | 분류 | 요구사항 |
|---|---|---|
| NFR-01 | 성능 | LLM을 호출하는 요청(ingest/query/lint)은 프론트엔드 타임아웃 900초, OpenAI 클라이언트 타임아웃 600초(`LLM_TIMEOUT`)를 허용한다 |
| NFR-02 | 신뢰성 | 페이지와 목차는 임시 파일에 쓴 뒤 교체(atomic write)해 쓰기 도중 파일이 깨지지 않게 한다 |
| NFR-03 | 신뢰성 | 쓰기 작업(ingest, 답변 저장, 로그, 규칙 저장)은 프로세스 내 재진입 가능 lock으로 직렬화한다 |
| NFR-04 | 신뢰성 | LLM 출력은 JSON 스키마 구조화 출력(strict)으로 받는다. 응답이 `incomplete`이거나 JSON이 아니면 502 오류로 처리한다 |
| NFR-05 | 보안 | API 키는 코드·파일에 저장하지 않고 환경변수에서만 읽는다 |
| NFR-06 | 보안 | slug와 원본 파일명을 정규화해 경로 조작(`../`)을 막는다 |
| NFR-07 | 이식성 | 위키 페이지는 표준 마크다운 + `[[slug]]` 링크라서 Obsidian 등에서 바로 열 수 있다. `data/`는 git으로 버전 관리할 수 있다 |
| NFR-08 | 설정 | 모든 한도와 기본값은 환경변수로 바꿀 수 있다 (SDS 4장) |
| NFR-09 | 추적성 | 모든 변경 작업과 사용 모델이 log.md에 남는다 |

## 5. 외부 인터페이스

### 5.1 HTTP API (요약)

자세한 요청·응답 형식은 [SDS 9장](02_SDS.md#9-api-명세)에 있다.

| 메서드 | 경로 | 기능 | 관련 요구사항 |
|---|---|---|---|
| GET | `/health` | 상태, 기본 모델, 페이지·원본 수, 지원 확장자 | FR-UI-02 |
| GET | `/models` | 모델 목록, 기본 모델·effort | FR-MDL-01 |
| GET | `/pages` | 페이지 메타데이터 목록 | FR-WIK-01 |
| GET | `/pages/{slug}` | 페이지 상세 + 링크 + 역링크 | FR-WIK-02 |
| GET | `/index`, `/log`, `/sources` | 목차, 로그, 원본 목록 | FR-WIK-03 |
| GET/PUT | `/schema` | 작성 규칙 조회·수정 | FR-SCH-02 |
| POST | `/ingest/file` | 파일 수집 (multipart) | FR-ING-* |
| POST | `/ingest/text` | 텍스트 수집 | FR-ING-02 |
| POST | `/query` | 질의 | FR-QRY-* |
| POST | `/query/save` | 답변 저장 | FR-QRY-07 |
| POST | `/lint` | 점검 | FR-LNT-* |

### 5.2 외부 시스템

- OpenAI Responses API (`client.responses.create`). 구조화 출력은 `text.format = {type: "json_schema", strict: true}`, 추론 강도는 `reasoning.effort`로 지정한다.
