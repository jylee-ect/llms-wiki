# LLM Wiki — 바이브코딩 재현 가이드

이 문서는 AI 코딩 에이전트(Claude Code 등)에게 [01_SRS.md](01_SRS.md)와 [02_SDS.md](02_SDS.md)를 주고 **같은 시스템을 다시 만드는 절차**를 정리한 것입니다.
단계별로 붙여 넣을 프롬프트와 단계마다 확인할 항목을 담았습니다.

---

## 1. 준비

| 항목 | 확인 방법 |
|---|---|
| Python 3.12 | `python --version` |
| OpenAI API 키가 환경변수 `GPT_API`에 있음 | PowerShell: `[bool]$env:GPT_API` → `True` |
| 키로 모델을 쓸 수 있음 | 아래 명령이 `OK`를 출력 |

```powershell
$body = @{ model = "gpt-6-luna"; input = "Say OK."; reasoning = @{ effort = "low" } } | ConvertTo-Json
(Invoke-RestMethod -Method Post -Uri "https://api.openai.com/v1/responses" `
  -Headers @{ Authorization = "Bearer $env:GPT_API" } -ContentType "application/json" -Body $body).status
```

새 폴더를 만들고 `docs/`(이 문서 3개)와 `samples/`를 복사해 둡니다.

---

## 2. 진행 원칙

- **한 번에 다 만들게 하지 말고 단계별로** 시킵니다. 단계마다 확인 항목을 통과한 뒤 다음 단계로 넘어갑니다.
- 프롬프트마다 "SDS를 따르라"고 명시합니다. 특히 **프롬프트 원문(SDS 8장)과 파일 형식(SDS 5장)은 글자 그대로** 옮기게 합니다. 이 부분이 달라지면 결과 품질이 달라집니다.
- 에이전트가 SDS와 다르게 하자고 제안하면, 이유를 들어보고 받아들일 경우 **SDS를 먼저 고친 뒤** 구현하게 합니다. 문서와 코드가 어긋나지 않게 하기 위해서입니다.
- 실제 `data/`를 더럽히지 않도록, 테스트는 `WIKI_DATA_DIR`을 임시 폴더로 바꿔서 합니다.

## 3. 단계별 프롬프트

### 단계 0 — 컨텍스트 주기

```
docs/01_SRS.md, docs/02_SDS.md, docs/03_재현_가이드.md를 모두 읽어줘.
이 문서대로 LLM Wiki 시스템을 단계별로 구현할 거야. 아직 코드는 쓰지 말고,
이해한 구조를 10줄 이내로 요약하고 문서에서 모호한 점이 있으면 알려줘.
```

✅ 확인: 요약에 "백엔드/프론트엔드 별도 프로세스", "DB 없이 파일 저장", "ingest 2단계 LLM 호출", "목차는 코드가 생성"이 들어 있다.

### 단계 1 — 프로젝트 골격과 환경

```
SDS 2·3장대로 디렉토리 구조, requirements.txt 2개, .gitignore, backend/app/__init__.py를 만들고
.venv 가상환경을 만들어 패키지를 설치해줘.
run_backend.ps1과 run_frontend.ps1도 SDS 12장의 명령으로 만들어줘.
```

✅ 확인: `.\.venv\Scripts\python.exe -c "import fastapi, openai, streamlit, pypdf, docx"`가 오류 없이 끝난다.

### 단계 2 — 설정, 오류, LLM 래퍼

```
SDS 4장, 6.1장, 6.2장대로 backend/app/config.py, errors.py, llm.py를 만들어줘.
MODELS 카탈로그와 resolve_options의 오류 메시지도 SDS 그대로.
다 만들면 complete_json으로 간단한 스키마({"slugs": [...]})를 gpt-6-luna effort low로 호출해서
JSON이 dict로 오는지 확인하는 테스트를 임시 스크립트로 돌려줘.
```

✅ 확인:
- 테스트 호출이 dict를 반환한다.
- `resolve_options("gpt-6.1-sol", "none")`과 `resolve_options("gpt-9")`가 `InputError`를 낸다.

### 단계 3 — 텍스트 추출

```
SDS 6.3장대로 backend/app/extract.py를 만들고,
samples/ 폴더의 파일 7개를 모두 extract_text로 읽어서 파일별 글자 수와 앞부분 70자를 출력해줘.
```

✅ 확인: 7개 모두 한글이 깨지지 않고 추출된다. PDF는 `[p.1]`로 시작한다.

### 단계 4 — 파일 저장소

```
SDS 5장(데이터 설계 전체)과 6.4장대로 backend/app/store.py와 default_schema.md를 만들어줘.
default_schema.md는 SDS 5.8장 원문 그대로.
그다음 WIKI_DATA_DIR을 임시 폴더로 바꾸고 아래를 확인하는 스크립트를 돌려줘:
- init() 후 AGENTS.md, wiki/index.md, wiki/log.md 생성
- Page 2개를 write_page → list_pages로 다시 읽었을 때 필드가 같음 (한글 제목, sources 리스트 포함)
- 본문에 [[b]]가 있는 페이지 a → a.links == ["b"], backlinks("b") == ["a"]
- slugify("가디언 AC-100") == "가디언-ac-100", normalize_slug("index") == "page-index"
- save_raw를 같은 이름으로 두 번 → 두 번째는 "-2"가 붙음
- rebuild_index 결과가 SDS 5.5 형식
```

✅ 확인: 모든 항목이 통과하고, 생성된 `.md` 파일의 frontmatter 값이 JSON 형식(`title: "..."`)이다.

### 단계 5 — 위키 로직

```
SDS 6.5장, 7장, 8장대로 backend/app/wiki.py를 만들어줘.
프롬프트 5개와 JSON 스키마 3개는 SDS 8장 원문을 한 글자도 바꾸지 말고 그대로 옮겨줘.
특히 7.1장의 "LLM이 본문을 못 본 기존 페이지는 덮어쓰지 않고 덧붙인다" 규칙을 꼭 구현해줘.
```

✅ 확인 (코드 리뷰):
- `extract_text`가 lock 밖에서 실행되고, `save_raw` 이후는 lock 안에서 실행된다.
- `_pick_pages`는 페이지가 없으면 LLM을 호출하지 않는다.
- `query`는 위키가 비어 있으면 LLM을 호출하지 않는다.
- `save_answer`는 LLM을 호출하지 않는다.

### 단계 6 — FastAPI

✅ 확인: 5.1장 표의 항목이 모두 통과한다.

SDS 10장대로 frontend/app.py를 만들어줘. UI 문구는 SDS에 적힌 한국어 그대로.

## 4. 자주 생기는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 한글 파일 내용이 깨짐 | `read_text()`/`write_text()`에 encoding 누락 (Windows 기본 cp949) | 모든 파일 입출력에 `encoding="utf-8"` |
| 콘솔 출력의 한글이 깨짐 | 콘솔 코드페이지 | 테스트 스크립트 실행 시 `PYTHONIOENCODING=utf-8` (기능 문제 아님) |
| curl로 올린 한글 파일명이 깨짐 | Git Bash curl의 인수 인코딩 | Python `requests`로 테스트 (Streamlit도 requests 사용) |
| `400 Unsupported value: 'minimal'` | 해당 모델이 지원하지 않는 effort | SDS 4장의 카탈로그만 사용 |
| `Invalid schema ... required` | strict 스키마에서 `required` 누락 | 모든 속성을 `required`에 넣고 `additionalProperties: false` |
| Streamlit `use_container_width` 경고 | 1.66에서 deprecated | `width="stretch"` |
| Streamlit에서 "widget ... default value ... Session State" 경고 | 위젯에 `index`/`value`를 주면서 같은 key의 session_state도 설정 | 위젯 생성 **전에** session_state만 설정하고 default 인자는 주지 않음 |
| 위키 탭으로 자동 이동이 안 됨 | Streamlit은 탭을 코드로 바꿀 수 없음 | 의도된 동작. `st.toast`로 안내 |
| AppTest가 파일을 못 찾음 | 상대 경로가 테스트 스크립트 위치 기준으로 해석됨 | `AppTest.from_file`에 절대 경로 전달 |
| AppTest `selectbox.set_value` 후 `ValueError: None is not in list` | `options`에는 `format_func`를 거친 **라벨**이 들어 있음 | `set_value`에는 라벨이 아니라 실제 값(id)을 넘김 |
| PDF에서 텍스트가 안 나옴 | 스캔 PDF (이미지) | 범위 밖 (OCR 미지원). 400 오류가 정상 |

## 6. 참고 실측값

원 구현에서 측정한 값입니다 (gpt-6-luna, effort medium). 모델 응답은 매번 달라지므로 생성되는 페이지 수와 정확한 문구는 다를 수 있습니다.

| 작업 | 소요 시간 |
|---|---|
| 짧은 메모 1개 ingest (빈 위키) | 약 17초 |
| samples 7개 순서대로 ingest | 문서당 39~79초, 합계 약 7분 → 페이지 29개 |
| samples ingest 시 갱신된 기존 페이지 수 | 2번째 문서부터 문서당 3~7개 |
| query | 약 7~8초 |
| lint (페이지 29개) | Luna·medium 약 33초 / Sol·low 약 10초 → 지적 4~5건(보관 기간 모순, 기한 지난 액션 아이템 등), 깨진 링크 4건, 고아 페이지 1개 |
| 같은 질문, 모델별 | Sol·none 4.4초 / 6.1 Sol·high 9.1초 / Luna·max 27.3초 |
